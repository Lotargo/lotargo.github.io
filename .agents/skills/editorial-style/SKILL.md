# Editorial Style

Use this skill for how publication text is written. Use `source-grounding` separately for factual support and links.

## Project punctuation rule

Never use the Unicode em dash `—` (U+2014).

Prefer, in this order:

1. rewrite the sentence;
2. split it into two sentences;
3. use a comma, colon, or parentheses;
4. if a dash is genuinely necessary, use `-` sparingly.

Do not replace every em dash mechanically with another dash. Prefer clearer sentence structure.

## Readability

- Lead with the most important information.
- Keep one main idea per paragraph.
- Prefer short sentences and compact paragraphs.
- Break up walls of text with descriptive headings and lists only when lists improve scanning.
- Use active voice where natural.
- Use concrete nouns and verbs instead of vague abstractions.
- Remove repeated conclusions, filler, inflated adjectives, and generic AI enthusiasm.
- Do not sacrifice technical precision for brevity.

## Voice

For articles about the author's own projects, experiments, architecture, or lessons:

- use first person naturally;
- sound like a practitioner describing real work;
- explain why a decision was made;
- distinguish current state from plans;
- state limitations without defensive disclaimers;
- avoid press-release and corporate-marketing language.

## Structure

Put the key point early in the sentence and paragraph. Prefer descriptive headings that tell the reader what the section contains.

A paragraph should normally cover one idea in the fewest sentences needed. A long paragraph is a signal to split or simplify it.

## Bilingual writing

Russian and English versions must preserve the same substantive claims, but they do not need literal sentence-by-sentence translation.

Keep technical terminology, links, image order, implementation status, and uncertainty consistent across languages.

## Practice basis

The ban on U+2014 is a project-specific house rule.
