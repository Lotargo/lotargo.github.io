# Статический блог в Telegram: публикация без отдельного бэкенда

У блога уже был детерминированный конвейер Article Bundle, поэтому для Telegram не понадобился отдельный сервер приложения. Он стал ещё одним адаптером распространения, который запускается через GitHub Actions после установки статьи.

## Путь публикации

Теперь production-цепочка выглядит так:

```text
Article Bundle
    ↓
рендер Markdown
    ↓
статические файлы GitHub Pages
    ↓
анонс в Telegram
    ↓
состояние публикации и обратная ссылка
```

Telegram-издатель читает установленный манифест статьи и русский Markdown-исходник. Из русского заголовка и описания он формирует компактный анонс, а затем добавляет кнопку на каноническую страницу статьи.

## Почему архитектура остаётся static-first

Здесь нет постоянно работающего процесса бота, отдельной базы данных, админ-панели или очереди задач. GitHub Actions предоставляет среду исполнения только в момент публикации.

Токен бота хранится в GitHub Secrets. Публичный идентификатор канала находится в Actions Variable. В самом репозитории сохраняются только несекретные метаданные публикации.

## Защита от дублей

После успешной отправки Telegram workflow записывает идентификатор сообщения, публичную ссылку на пост, адрес статьи и хеш исходника в `telegram-publications.json`.

При обычном повторном запуске скрипт видит уже зарегистрированный slug и пропускает его. Поэтому перезапуск workflow безопасен и не создаёт случайных дублей.

## Ссылки в обе стороны

В Telegram-посте есть кнопка на полную статью. После сохранения возвращённого `message_id` страница статьи может показать обратную ссылку на Telegram-публикацию и связанную ветку обсуждения.

Получается замкнутый маршрут распространения:

```text
анонс в Telegram → полная статья → обсуждение в Telegram
```

## Практичная граница первой версии

Первая production-версия публикует компактный анонс, а не пытается полностью воспроизвести в Telegram каждую конструкцию Markdown. Так доставка остаётся предсказуемой, а поддержку галерей, длинных публикаций и media group можно добавлять отдельно.

Главное уже работает: одна исходная статья теперь питает и сайт, и русскоязычный Telegram-канал, не создавая вторую независимую систему контента.
