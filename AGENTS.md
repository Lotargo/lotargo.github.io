# Repository publishing rules

These rules apply to all public-facing prose produced in this repository.

## Writing

- Never use the Unicode em dash `—` (U+2014) in publication text.
- Prefer a period, comma, colon, parentheses, or a rewritten sentence. If a dash is unavoidable, use `-` sparingly.
- Keep public prose direct, readable, and specific.
- For publication writing, apply the repo-local `editorial-style` skill.

## Sources

- Never invent a source, citation, author, publication, URL, quote, version, benchmark, or attribution.
- When a factual claim comes from external information or could reasonably be disputed, provide a real descriptive link to the source near the claim.
- Prefer primary and official sources when they exist.
- If a trustworthy source cannot be verified, omit the claim or state the uncertainty instead of fabricating support.
- For research, attribution, and citations, apply the repo-local `source-grounding` skill.

## Publication workflows

- Use `write-blog-article` for full blog article drafting and revision.
- Use `prepare-telegram-edition` for Telegram text. Telegram must be a short self-contained article, not a copied blog lead or a one-line announcement.
- Every new Telegram article publication must attach at least one supported image and use the project Telegram validation flow.
- Validate before install, staging, commit, or external publication.
